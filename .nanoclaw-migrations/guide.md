### OneCLI agent identifier must start with a letter

**Intent:** OneCLI's `/api/agents` requires identifiers to start with a letter (1–50 chars, lowercase + digits + hyphens). Agent group ids are `randomUUID()`-generated and often start with a hex digit, which OneCLI rejects. This adds a reversible `g-` prefix at the OneCLI boundary: applied when registering/spawning an agent, reversed when reading `externalId` back for approval routing.

**Files:**
- `src/onecli-identifier.ts` — **new file, copy verbatim, no changes needed regardless of upstream restructuring** (pure two-function utility, no dependencies on other NanoClaw modules):

```typescript
/**
 * Agent group ids generated by `randomUUID()` often start with a hex digit,
 * but OneCLI's `/api/agents` requires identifiers to start with a letter
 * (1-50 chars, lowercase + digits + hyphens). The forward helper prefixes
 * any non-letter-leading id; ids already matching `/^[a-z]/` (UUIDs starting
 * with a-f, `ag-...` legacy, etc.) pass through unchanged.
 *
 * Reverse only strips the prefix when the suffix would itself fail the
 * forward rule — that way a legitimate `g-<letter>...` id round-trips
 * intact instead of being mis-stripped to its tail.
 */
const ONECLI_PREFIX = 'g-';

export function toOneCliIdentifier(agentGroupId: string): string {
  return /^[a-z]/.test(agentGroupId) ? agentGroupId : `${ONECLI_PREFIX}${agentGroupId}`;
}

export function fromOneCliIdentifier(identifier: string): string {
  if (identifier.startsWith(ONECLI_PREFIX)) {
    const rest = identifier.slice(ONECLI_PREFIX.length);
    if (!/^[a-z]/.test(rest)) return rest;
  }
  return identifier;
}
```

### Run task pre-scripts as Node ES modules when detected

**Intent:** Task pre-scripts were always run as bash. Some scripts are written as Node ES modules (`import`/`export` syntax, or a `#!.../node` shebang) and need `node`, not `bash`, to execute. Adds runtime auto-detection; bash remains the default for anything else.

**Files:** `container/agent-runner/src/scheduling/task-script.ts` (same path on upstream as of `294ef2a`, `runScript` still hardcodes `bash` there — this is a clean additive change).

**How to apply:**

1. Add near the top of the file, after existing interfaces:
   ```typescript
   export interface ScriptRuntime {
     command: string;
     extension: string;
     args: (scriptPath: string) => string[];
   }

   export function selectScriptRuntime(script: string): ScriptRuntime {
     const trimmed = script.trimStart();
     const firstLine = trimmed.split(/\r?\n/, 1)[0] ?? '';

     if (
       firstLine.startsWith('#!') &&
       (firstLine.includes('/node') || firstLine.includes('env node'))
     ) {
       return nodeRuntime;
     }

     if (/^(import|export)\s/.test(trimmed)) {
       return nodeRuntime;
     }

     return bashRuntime;
   }

   const bashRuntime: ScriptRuntime = {
     command: 'bash',
     extension: 'sh',
     args: (scriptPath) => [scriptPath],
   };

   const nodeRuntime: ScriptRuntime = {
     command: 'node',
     extension: 'mjs',
     args: (scriptPath) => [scriptPath],
   };
   ```

2. In `runScript`, replace the hardcoded bash path/command with runtime selection. Upstream's current version:
   ```typescript
   export async function runScript(script: string, taskId: string): Promise<ScriptResult | null> {
     const scriptPath = path.join('/tmp', `task-script-${taskId}.sh`);
     fs.writeFileSync(scriptPath, script, { mode: 0o755 });

     return new Promise((resolve) => {
       execFile(
         'bash',
         [scriptPath],
         { timeout: SCRIPT_TIMEOUT_MS, maxBuffer: SCRIPT_MAX_BUFFER, env: process.env },
         (error, stdout, stderr) => { ... }
       );
     });
   }
   ```
   Change to:
   ```typescript
   export async function runScript(script: string, taskId: string): Promise<ScriptResult | null> {
     const runtime = selectScriptRuntime(script);
     const scriptPath = path.join('/tmp', `task-script-${taskId}.${runtime.extension}`);
     fs.writeFileSync(scriptPath, script, { mode: 0o755 });

     return new Promise((resolve) => {
       execFile(
         runtime.command,
         runtime.args(scriptPath),
         { timeout: SCRIPT_TIMEOUT_MS, maxBuffer: SCRIPT_MAX_BUFFER, env: process.env },
         (error, stdout, stderr) => { /* unchanged body */ }
       );
     });
   }
   ```
   Only the script-path extension and the `execFile` command/args come from `runtime` — the callback body (error handling, JSON parsing of stdout) is unchanged.

3. Copy `container/agent-runner/src/scheduling/task-script.test.ts` as-is — it only tests `selectScriptRuntime()` (bash default, ES-module detection, node-shebang detection) and doesn't touch anything upstream-specific.
